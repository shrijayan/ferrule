Each row is a public Stainless Python SDK regenerated nightly by `parity.yml` from its public
`stainless.yml` and OpenAPI spec, then compared with its last Stainless-generated commit. Click a
column header to sort.

## Methodology

The oracles and their pinned commits live in
[`oracles/manifest.yaml`](https://github.com/shrijayan/ferrule/blob/main/oracles/manifest.yaml).
How each config repo is paired with its SDK commit is recorded in
[ADR 0009](https://github.com/shrijayan/ferrule/blob/main/docs/adr/0009-oracle-configs.md), and
how the inputs are pinned by digest in
[ADR 0010](https://github.com/shrijayan/ferrule/blob/main/docs/adr/0010-oracle-snapshot-digests.md).

| Column | Meaning |
| --- | --- |
| Oracle | The oracle group in the manifest. |
| SDK repo @ sha | The Stainless-generated SDK and the commit Ferrule's output is compared with. |
| Breaking | Public API changes that would break a user (griffe diff: removed or renamed names, changed signatures). The goal is 0. |
| Additive | Public API additions that break nobody. |
| Closeness | Share of the SDK's source text that matches after normalization (formatting, import order). |
| Tests passed / failed | The SDK repo's own test suite run against the generated code and a mock server; failed includes errors. `—` means tests were not run. |
| Deterministic | Two generations from the same inputs were byte-identical. |
| Generated | The date of the nightly run that produced the row. |
