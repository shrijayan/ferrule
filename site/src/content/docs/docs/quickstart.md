This page takes a Stainless-generated Python SDK repository and switches its generator to
Ferrule. Your users keep importing the same package, with the same names and arguments.

:::caution[Pre-alpha]
Ferrule is not on PyPI yet, so for now you build it from source (step 1). The 0.1 release is
planned to bring this down to `uvx ferrule adopt .`. Check the
[fidelity board](/ferrule/docs/fidelity/) to see how close Ferrule gets on SDKs like yours.
:::

## What you need

- A clone of your SDK repository, with its git history. Ferrule looks for the last commit made
  by `stainless-app[bot]`, so a shallow clone is not enough.
- Your `stainless.yml`. Many SDK repositories don't contain it; export it from Stainless or take
  it from your config repository.
- [mise](https://mise.jdx.dev). It installs the pinned Rust toolchain, Python and uv. Node is
  not needed to generate an SDK.

## 1. Build Ferrule

```bash
git clone https://github.com/shrijayan/ferrule
cd ferrule
mise install                                  # Rust, Python, uv
mise run install                              # Python dependencies
cargo build --release -p ferrule-gen          # converter, Forge and plugin in one binary
```

`ferrule` finds the binary at `target/release/ferrule-gen` in the checkout. If you build it
somewhere else, pass `--gen PATH` or set `FERRULE_GEN`.

## 2. Do a dry run

From the Ferrule checkout, point `adopt` at your SDK:

```bash
uv run ferrule adopt ~/code/acme-python --config ~/code/acme-config/stainless.yml --dry-run
```

The dry run rescues the spec, regenerates the SDK and finds your hand edits, all inside a
temporary worktree, then stops. No lock file, workflow or branch is written.

## 3. Adopt

```bash
uv run ferrule adopt ~/code/acme-python --config ~/code/acme-config/stainless.yml
```

```text
✓ read .stats.yml → spec URL + hash
✓ rescued spec to ./openapi.json (hash ok)
✓ converted stainless.yml → overlays
✓ copied runtime from your repo (you own it)
✓ found 3 hand edits → .ferrule/patches/
✓ generated via ferrule-gen (forge + ferrule-python)
✓ committed 'Switch SDK generation to Ferrule' on local branch ferrule/adopt (not pushed)
ferrule verify --against 1a2b3c4
public API: 0 breaking · 6 additive
text closeness: 97.8%
```

`adopt` works in a temporary git worktree, so your checkout and current branch are never
touched. It saves the spec your `.stats.yml` points to (checking its md5), regenerates the SDK,
re-applies your hand edits, then runs `verify` against your last Stainless commit. The command
exits with status 1 if anything public would break.

## 4. Review the branch

Everything lands as one commit on the local branch `ferrule/adopt`:

| File | What it is |
| --- | --- |
| `openapi.json` (or `.yml`) | The rescued spec. It used to live in a bucket you don't control. |
| `.ferrule/patches/*.patch` | One patch per hand-edited generated file, re-applied on every regeneration. |
| `ferrule.lock` | The exact spec, config, Ferrule and `ferrule-gen` versions and Forge commit behind this output. |
| `.github/workflows/sdk.yml` | The workflow that keeps the SDK regenerating (step 6). |
| Generated files | Regenerated by Ferrule. Expect only the header line to change. |

```bash
cd ~/code/acme-python
git diff main...ferrule/adopt --stat
```

Breaking changes are listed under the `verify` summary, one per line. Additive changes are names
the spec has gained since your last Stainless release; they break nobody.

## 5. Push, test, merge

```bash
git push -u origin ferrule/adopt
gh pr create --fill
```

Your existing CI runs your existing tests against the regenerated code. When it is green, merge.
Your next release is an ordinary patch release: nothing your users import has changed.

## 6. Keep it regenerating

`adopt` adds `.github/workflows/sdk.yml`. On every change to the spec or config, and nightly, it
regenerates the SDK, runs `verify`, and opens a pull request labelled `major`, `minor` or
`patch`. An unlabelled breaking change fails the check.

:::note
Before you merge, replace the `uses:` line of the Ferrule step in `sdk.yml` with
`shrijayan/ferrule/action@<sha>`, pinned to a commit of this repository. The action has no
release yet, so `adopt` writes a placeholder. The inputs are described on the
[GitHub Action](/ferrule/docs/action/) page.
:::

## When something fails

Every error has a `FER` code, the file or setting it refers to, and a suggested fix, for
example `ferrule adopt: FER4101 …` when the rescued spec doesn't match its hash. The
[commands](/ferrule/docs/commands/#errors) page lists the families. If you are stuck,
[open an issue](https://github.com/shrijayan/ferrule/issues) with the FER code and the command you
ran.
