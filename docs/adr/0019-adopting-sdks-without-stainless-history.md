# 0019. Adopting an SDK that Stainless never generated

## Context and problem statement

`shrijayan/opencode-python-sdk` (ADR 0015) was built by its own generator, not by Stainless. Ferrule's
adoption flow assumed a Stainless history: `adopt` diffed against the last Stainless commit,
`--runtime-from` copied a Stainless runtime, and `verify` treated every difference in spelling
from today's Stainless runtime as a change. The user asked for this SDK to be generated by Ferrule
for real, with its own features kept, accepting breaking changes where they are the cost of the
Stainless layout. What changes when an SDK has no Stainless history, and what does "breaking"
mean for it?

## Decision drivers

- Stainless output is still the spec for everything generated (plan §8); a foreign SDK's layout
  is not copied into the generator.
- The SDK's hand-written features must survive every regeneration without manual steps.
- `verify` must report real API changes, not two runtimes spelling the same API differently.
- Every behaviour added for this SDK is a Stainless config feature or a generic fix, checked
  against an oracle where one exists.

## Considered options

1. Teach the generator the SDK's own layout (flat `types/_generated.py`, `NOT_GIVEN`, its own
   pagination), so adoption is non-breaking.
2. Generate the Stainless layout and keep the SDK's features as custom code, accepting a
   documented list of breaking changes.
3. Leave the SDK on its own generator and only produce a comparison.

## Decision outcome

Chosen option 2. The user accepted the breaks, and option 1 would fork the generator for one SDK
against plan §8.

- **Adopt without Stainless history.** `adopt` uses HEAD as the base when no Stainless commit
  exists; `--runtime-from` renders Ferrule's own runtime when the SDK has no `_utils/`; adopt
  commits the rendered runtime and records the generation on a `generated` branch with a
  `Ferrule-Generated-From:` trailer.
- **Regenerate by three-way merge.** `ferrule regenerate` (and the GitHub Action) commits each
  generation on `generated` and merges it into the branch from the generation that branch last
  took. Custom code lives in `lib/` and in files the lock does not list; `keep_files` covers
  project files; `examples/` stays the user's except `examples/agent/`, which Ferrule writes.
- **Verify normalises runtime spellings.** `NOT_GIVEN`/`omit` default changes and
  `cached_property` kind changes (also for a class re-exported from another module) are listed
  as `normalized`, not breaking.
- **Generic features this needed**, each test-first and from Stainless config or oracles:
  binary request bodies, `unwrap_response`, `…Param` TypedDict twins and `shared_params`,
  `api_`-prefixed parameters named like request options, HTTP basic auth, a client option's
  `default`, `skip_test_reason`, pagination schemes for the runtime, union responses cast as
  knock-mgmt-python does, pages and streams checked as honcho-python-core and the Stainless
  opencode SDK do, examples of named aliases and models, `object` for a typeless schema.
- **The SDK's config** (`oracles/configs/opencode-python-sdk/stainless.yml`) names every schema
  as a model under the SDK's names, except response envelopes the SDK unwraps.

### Consequences

- Good: the SDK regenerates from `openapi.json` and `stainless.yml` with no manual step; its own
  tests, the generated tests (against the mock), ruff, pyright and mypy pass.
- Good: every fix applies to every Ferrule SDK; golden digests that changed (pagination
  schemes, unwrap) are listed for human review.
- Bad: 697 breaking changes against the SDK's last release (inline types nested in their
  parent's module, private runtime members, `*ErrorBody` and `Unknown*` types, a few renamed
  parameters). They are listed in the SDK's PR and CHANGELOG.
- Bad: the SDK mixes licences: hand-written code MIT, generated code and runtime Apache-2.0
  (`NOTICE`). The user decides before merging.
- Neutral: `adopt:gate` checks this SDK from its adoption branch (no drift, tests pass, breaking
  count at most the recorded 697) instead of replaying the adoption.
