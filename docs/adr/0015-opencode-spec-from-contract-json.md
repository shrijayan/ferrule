# 0015. The opencode SDK's spec comes from our own contract.json converter

- Status: Accepted
- Date: 2026-10-23
- Deciders: Ferrule maintainers (made on the user's behalf while they were away)

## Context and problem statement

`shrijayan/opencode-python-sdk` is the user's own SDK and the last migration target. It was
never generated by Stainless: there is no `.stats.yml` and no OpenAPI spec. Its `codegen/`
builds it from `spec/contract.json`, which `codegen/extract` exports from the Effect `HttpApi`
definitions in `@opencode/protocol`. `ferrule generate` needs an OpenAPI document. How do we get
one without running third-party code (the npm package or `opencode serve`)?

## Decision drivers

- Never run the SDK's or OpenCode's code; the checkout is data.
- Deterministic: the same `contract.json` gives byte-identical OpenAPI.
- The question we can answer is "what public API would change if this SDK moved to Ferrule",
  not "is Ferrule byte-identical to Stainless here": there is no Stainless output to compare to.

## Considered options

1. Export OpenAPI from `@opencode/protocol` with Effect's `HttpApi` OpenAPI generator.
2. Fetch the document from a running `opencode serve`.
3. Write a pure, stdlib converter from `contract.json` to OpenAPI 3.1.

## Decision outcome

Chosen option 3, `scripts/opencode/contract_to_openapi.py`, because it runs no third-party code
and is reproducible from the pinned SDK commit alone. It maps groups to tags, endpoints to
operations, inputs to parameters and request bodies, success kinds and tagged errors to
responses, and `$defs` to `components.schemas`. It makes two shape choices, both documented in
the module:

- object-typed query parameters use `style: form, explode: true` (Forge covers only `form`);
- Effect's `Struct` + `Record` intersection (`allOf: [{type: object, additionalProperties: X}]`)
  is folded into the parent object's `additionalProperties`.

The stainless.yml in `oracles/configs/opencode-python-sdk/` is drafted from the SDK's `api.md`
by `scripts/opencode/api_md_to_config.py`, the way an adopter would write it (ADR 0009).

The bar for this SDK is the `ferrule verify` public-API diff against release `v0.2.3`, recorded
in `docs/opencode-migration.md`. Byte parity is not a goal, and differences caused by the SDK's
own generator choices are not Ferrule bugs unless they also show up on a Stainless oracle.

### Consequences

- Good: no third-party code runs; the spec is reproducible from `contract.json` (md5 recorded).
- Good: generic plugin and runtime gaps found here are reported to their owners.
- Bad: the converter is opencode-specific; it is not a general Effect-to-OpenAPI tool and is not
  part of the shipped `ferrule` CLI.
- Bad: names in the spec come from Effect identifiers (`Session.Message.Info`), not from an
  OpenAPI author, so model names differ from the SDK's own until `models:` is configured.
