The situation

      
Your generator is going away. Your users aren't.

      
Thousands of developers import the SDK you shipped. Every class name, every keyword argument,
        every with_raw_response is a promise. You have three ways forward.

    

    

      

        Option 01
        
Switch to another generator

        
It has its own house style. Class names move, params change shape, and your users find out from a stack trace. Some free tiers put copyleft code inside your SDK.

        Your users rewrite their code
      

      

        Option 02
        
Freeze it and hand-maintain

        
Works until the API ships a new endpoint. Then someone writes pagination by hand at 11pm, and the SDK slowly drifts away from the spec it was built from.

        The SDK rots
      

      

        Option 03 · Ferrule
        
Keep the SDK. Swap the engine.

        
Same spec, same stainless.yml, same Python, regenerated on an open engine you control. A public API diff proves it before you merge.

        Nobody notices. That's the point.

How it works

      
Five stages. One of them borrowed.

      
We didn't build another generator. Forge, Cloudflare's Apache-2.0 engine, parses the spec. Ferrule adds everything it doesn't do: reading your config, writing Stainless-shaped Python, and proving it.

    

    

      

        
Inopenapi.ymlstainless.ymlyour hand editslast release

        
OutPython SDKapi.md.stats.ymlferrule.lockverify report

      

      

        

        
01
Convert
Validate stainless.yml against the public schema, apply editions and transforms, annotate the spec.
converter · TypeScript

        
02
Forge
A pinned Forge commit parses the annotated spec and runs our WebAssembly plugin.
dependency · never forked

        
03
Emit
An adapter maps Forge data into our own model; pure emitters write every SDK file.
python-plugin · TS → WASM

        
04
Finish
Copy the runtime from your repo, format with ruff, merge your custom code back on.
migrate · Python

        
05
Verify
Diff the public API, type-check, run tests against a mock, give a semver verdict.
migrate · Python

01Rescue the spec
Your .stats.yml points at a spec in a bucket you don't own. Ferrule saves it and checks the hash.

          
02Convert and generate
Your config becomes Forge overlays. Your runtime is copied from your own repo, so you keep owning it.

          
03Record your hand edits
Custom code becomes patches that survive every regeneration via three-way merge.

          
04Open a pull request
With a verify report attached, so the review is about evidence, not trust.

Questions

      
The fine print, in plain words.

    

    

      
Will my users have to change any code?
        
No, and Ferrule checks that for you. ferrule verify diffs the public API of the new output against your last Stainless release with griffe, then runs your own tests against it. The target is zero breaking changes, and the GitHub Action fails if one sneaks in without a label.

      
What happens to the code we wrote by hand?
        
Adoption records your hand edits as patches. Every regeneration lands on a generated branch and is merged three ways, with an AST-aware fallback. Your lib/ folder and any kept files are never touched. Real conflicts become a pull request for a human.

      
Is the generated SDK really ours?
        
Yes. In adopt mode the runtime is copied from your own repository, so it stays under the licence you already ship. The SDK has no dependency on Ferrule or Forge, and the generated code carries no obligations.

      
Is Ferrule affiliated with Stainless or Cloudflare?
        
No. Ferrule is an independent Apache-2.0 project. It uses Cloudflare's open-source Forge engine as a pinned dependency, and treats public Stainless-generated SDKs (which are Apache-2.0) as the reference output.

      
How ready is it?
        
Pre-alpha. The converter, plugin and runtime are done, and the OneBusAway SDK regenerates with zero breaking changes and all 1,110 of its own tests passing. Adoption tooling is being hardened against more real SDKs now; the public alpha (0.1) follows. Watch the fidelity board.

      
Only Python?
        
For now, on purpose. One language done perfectly beats four done approximately. TypeScript comes after Python is proven, and only if teams ask for it.

      
What does it cost?
        
Nothing. Everything that runs on your machine is open source. If there is ever a paid offering, it will be optional services like fixed-fee migrations with a signed fidelity report, never a token you need to generate code.
