# Human actions

Things the autonomous build must not do. Each has exact steps. The repository lives at
`shrijayan/ferrule` (Apache-2.0); a move to an org can come later via Settings → Transfer.

1. **Name check and registration** — confirm `ferrule` is free on PyPI and npm; reserve PyPI `ferrule` and npm `@ferrule/python-plugin`. The npm reservation is no longer needed (2026-10-25): the plugin is now the Rust crate `crates/python-plugin`, shipped inside the `ferrule-gen` binary, and nothing is published to npm (ADR 0014).
2. [x] **Create the remote and push** — `shrijayan/ferrule`, public, `main` pushed.
3. [x] **Rulesets** — `main`: PR with 1 approval (stale dismissed, last-push approval, threads resolved), squash/rebase only, linear history, signed commits, no force-push/deletion, strict status checks `ci`, `dco`, `commitlint`, `codeql (javascript-typescript|python|actions)`, `zizmor`, `gitleaks`, `dependency-review`. `release-tags`: `v*` and `*-v*` tags cannot be updated or deleted. Repository admins bypass both, so a solo maintainer can merge their own PRs; remove the bypass once there is a second maintainer. Existing commits are unsigned: set up commit signing (`git config commit.gpgsign true` with an SSH or GPG key) before pushing as a non-admin.
4. **Trusted publishing** — add PyPI and TestPyPI trusted publishers for `shrijayan/ferrule`, workflow `release.yml`, environment `release`; npm: enable provenance and OIDC trusted publishing for `@ferrule` (no longer needed since ADR 0014: no npm package is released).
5. [x] **GitHub Pages** — source set to GitHub Actions.
6. [x] **No apps needed** — daily dependency updates come from `.github/dependabot.yml`; DCO is checked by `dco.yml`; Scorecard runs via workflow. `renovate.json` removed.
7. **Forge RFC** — open an issue on cloudflare/forge describing the Python plugin and migration tools; link RFC #45. Draft: `docs/rfcs/forge-python-plugin.md`.
8. **Legal review of runtime reuse** before 0.1 (plan §4 legal guardrails).
9. [x] **`release` environment** — created, deployments limited to `main`, `@shrijayan` required reviewer.
10. [x] **Security settings** — dependency graph and Dependabot alerts on, Dependabot security updates on, daily version updates via `.github/dependabot.yml`, secret scanning and push protection on, private vulnerability reporting on, code scanning via the CodeQL job in `security.yml` (default setup left off).
11. **release-please token** — add a GitHub App or fine-grained PAT so release PRs trigger CI (Actions may already create PRs: workflow permissions are read-only by default with PR creation allowed).
12. [x] **CODEOWNERS and links** — replace `@ferrule-dev/maintainers` with `@shrijayan`, and `ferrule-dev/ferrule` / docs base URL with `shrijayan/ferrule` (`.github/ISSUE_TEMPLATE/config.yml`, `.github/CODEOWNERS`, docs site config).
13. [ ] **Forge upstream issues** — after the RFC, open issues on cloudflare/forge for gaps G2 (document extensions on `forge-info`) and G3 (schema extensions on `model-info`/`field-info`), citing `docs/forge-gaps.md`; mention G10 (`Group` back-pointer) and G11 (document method order).
14. [ ] **Forge leniency issues** (cloudflare/forge, after the RFC; see docs/forge-gaps.md G22–G23): (a) accept a JSON `null` inside a `type` array (YAML `type: [array, null]`) or report its JSON pointer; (b) accept the string shorthand `discriminator: <propertyName>`; (c) include the JSON pointer of the failing node in every deserialisation error. Ferrule normalises both in `crates/converter/src/normalize.rs` until then.
15. [ ] **Forge reader issues from the Tier 1 corpus** (cloudflare/forge, after the RFC; see docs/forge-gaps.md G25–G26). Suggested text:
    - *Query parameter styles other than form.* "`check_param` refuses any `in: query` parameter whose `style` is not `form`, so the whole document fails on Stripe (`expand`, `style: deepObject`) and OpenAI (`metadata`). Could `Location::Query` carry the style (`deepObject`, `spaceDelimited`, `pipeDelimited`) so generators decide how to serialise? Repro: one GET with `{name: expand, in: query, style: deepObject, schema: {type: object}}`."
    - *Equal names for distinct wire names.* "`check_names` compares `Name`s, which are lower-case words, so `+1`/`-1` (GitHub reactions), `DateCreated<`/`DateCreated>` (Twilio) and `notificationUrl`/`notification_url` (Cloudflare) are refused even though they are different properties. Could the error carry the JSON pointer and suggest `x-fern-property-name`, or could symbols such as `+`, `-`, `<`, `>` become words? Repro: `properties: {'+1': {type: integer}, '-1': {type: integer}}`."
    Ferrule works around both in `crates/converter/src/normalize.rs` until then.
16. [ ] **Forge: report an Operation Object that is a `$ref`** (cloudflare/forge, after the RFC; see docs/forge-gaps.md G32). Suggested text:
    - *An operation written as `$ref` is read as empty.* "DigitalOcean's public spec writes every operation as `get: {$ref: 'resources/droplets/droplets_list.yml'}`. OpenAPI does not allow `$ref` on an Operation Object, and Forge reads each one as an operation with no parameters, body or responses, without a diagnostic, so a generator produces 858 empty methods and reports success. Could Forge refuse it, or report the JSON pointer and the referenced file? Repro: `paths: {/a: {get: {$ref: 'a_get.yml'}}}`."
    Found by the Tier 1 corpus run of 2026-10-26 (docs/PROGRESS.md).
