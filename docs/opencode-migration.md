# opencode-python-sdk migration

`shrijayan/opencode-python-sdk` is generated by Ferrule on its `ferrule/adopt` branch:
[shrijayan/opencode-python-sdk#25](https://github.com/shrijayan/opencode-python-sdk/pull/25), not
merged. Decision records: ADR 0015 (the spec from `contract.json`) and ADR 0020 (adopting an SDK
Stainless never generated).

## Pipeline

```text
spec/contract.json ─contract_to_openapi─▶ openapi.json ─config_models─▶ stainless.yml ─ferrule─▶ SDK
```

| Step | How | Result |
| --- | --- | --- |
| OpenAPI 3.1 | `scripts/opencode/contract_to_openapi.py` | 142 operations; byte-identical on re-run |
| Models and casings | `scripts/opencode/config_models.py` | every schema a `$shared` model under the SDK's name, except the 3 envelopes the SDK unwraps; `custom_casings`; `unwrap_response: data` on the 36 methods that returned `data` |
| Config | `oracles/configs/opencode-python-sdk/stainless.yml` | resources from `api.md`, basic auth, cursor pagination, ten-minute timeout, `keep_files`, `skip_test_reason` on 2 methods |
| Generate | `ferrule adopt` (first), then `ferrule regenerate` | no FER errors; the package imports |

Both scripts are copied into the SDK (`scripts/opencode/`, Apache-2.0 headers kept), where its CI
checks the committed `openapi.json` and `stainless.yml` against `spec/contract.json`.

### Breaking changes, by cause (accepted by the user)

| Count | Cause |
| --- | --- |
| 268 | Inline types the old generator exported from `opencode.types` are nested in their parent model's module, as Stainless nests them |
| 323 | Members of private modules (`_base_client`, `_exceptions`, `_errors`, `_pagination`, `_response`, `types._generated`, ...) |
| 34 | `*ErrorBody` types: Forge exposes only 2XX responses (gap G29) |
| 32 | `Unknown*` fallback classes of unions |
| 18 | Envelope and wrapper types of methods that return `data` |
| 4 | `file.write`: `body=` instead of `payload=` |
| 4 | `rpc.call`: `rpc_id` keyword-only |
| 2 | `shell.create(timeout=)` is `api_timeout=` |
| 2 | `SyncResources` / `AsyncResources` mixins |
| 6 | `client.page()`, `client.stream()`, `__repr__` |
| 4 | Client base classes; `base_url` keyword-only |

## Custom code kept

`src/opencode/lib/` (the exported clients and resource subclasses, `session.run`, helpers), the
hand-written modules (`_events.py`, `_rpc.py`, `_pty.py`, `_server.py`, `_service.py`,
`service.py`, `testing.py`, `_errors.py` on Ferrule's exceptions), an export block appended to
the generated `__init__.py`, `tests/custom/`, and the project files in `keep_files` (licence,
README, pyproject, CI). `ferrule regenerate` merges each generation from the `generated`
branch three ways, so edits to generated files survive too.

## What was fixed in Ferrule (test-first)

| Area | Fix |
| --- | --- |
| python-plugin | binary request bodies; `api_` prefix for parameters named like request options; HTTP basic auth; client option `default`; `unwrap_response` with `_wrappers.py`; `…Param` TypedDict twins and `shared_params`; examples of named aliases and models, keyed by Python name; pages and always-streaming methods in API tests; `skip_test_reason`; no header-validation test for optional credentials; union responses, pages and streams cast as Stainless does; `object` alias for a typeless schema; no unused imports in a resource without methods |
| converter | `x-ferrule-page-schemes`, `x-ferrule-unwrap` (FER1007), `x-ferrule-skip-test` |
| runtime | `page_schemes()` from the config's pagination |
| migrate | `--runtime-from` a non-Stainless SDK renders Ferrule's runtime; adopt without Stainless history; adopt commits the rendered runtime, the `generated` branch and the trailer; `ferrule regenerate`; `keep_files` comments; verify's `normalized` list (also for a class that moved module); agent recipes under `examples/agent/` are regenerated |
| action | `ferrule regenerate` on `ferrule/regenerate`, pushes `generated`; fails on a merge conflict; "bring your own App token" and cross-repo dispatch docs |
| scripts | `format: binary` payloads; NonEmptyArray `prefixItems` folded; `x-opencode-unwrap-data`; the envelopes the SDK unwraps are no models |

## What remains

1. Forge (upstream): non-2XX response models (G29), `prefixItems` (G30), `deepObject` query
   parameters; drafted in `docs/HUMAN-ACTIONS.md`.
2. Runtime: `BaseModel.model_dump` lacks pydantic 2.13's `polymorphic_serialization`
   parameter, so the SDK pins pydantic < 2.13 in its dev group.
3. migrate: `ferrule regenerate` should refuse a dirty work tree.
4. The SDK PR: the user decides on the licence split (MIT hand-written, Apache-2.0 generated)
   and merges; then bump the action pin in its `sdk.yml` to the merged Ferrule commit.
5. Golden digests changed by the pagination-scheme and unwrap extensions (honcho, knock,
   knock-mgmt, ogx) need a human review.
